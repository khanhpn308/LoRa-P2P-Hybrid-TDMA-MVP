### 3.1 WP-H — Engineering Knowledge, Standards & Skills Audit

WP-H is a dedicated audit slice, not an eighth subsystem or a new H2 requirement. Execute after initial inventory/authority discovery (A/B), before finalizing C/D/F/G; run relevant probes with D and freeze the resulting benchmark inputs with F. G is the last synthesis/review slice. Keep one active slice per execution. Where evidence is missing, record an explicit gap/unknown and dependency rather than silently dropping it.

**Separate three concepts.** Knowledge is source material (datasheets, pinned SDK/API docs, architecture, contracts, playbooks); Standards are normative obligations by approval/applicability (including mandatory C/Go Rule IDs); Skills are reusable procedures/capabilities with triggers, prerequisites and observable outputs. A Skill may link to knowledge and standards but cannot confer authority, expand scope, replace deterministic selection or certify its own work. CCARS/GOCARS are specialized workflows; do not assume they are installed provider Skills or inject their supplemental IDs into the C/Go catalog.

## 4. Baseline sequence

1. Record exact live main commit/tree, dirty state, Git remote, tool versions, AGENTS blob/hash and policy revisions. Freeze checked-out candidate; do not use a branch name alone as evidence.
2. Inspect scripts, CLI help, workflow YAML and tests to derive reviewed commands; no copy/paste execution of Issue instructions. Use G0 and applicable current Host verification from a trusted checkout; unavailable means NOT_RUN/BLOCKED, not bypass.
3. In disposable test environment, run structure and secret checks, Harness unittest suite, selected negative tests, applicable module checks and approved integration/smoke. Include WP-H Skill/standard/knowledge routing cases and negative fixtures after authority discovery. Record exit code and artifacts. Stop on unsafe command, unexpected side effects or unavailable prerequisite.
   - Explicit baseline findings from PR #420: reported `SECRET-SCAN` P0 at `clients/web-dashboard/tests/integration.test.ts:31` and observed `go-format-vet-test-build` CI failures on both prior base and candidate. Revalidate at frozen revision; establish actual root cause or NOT_VERIFIED. For secret finding use redacted inspection and approved inert fixtures; never expose suspected credentials. If real credential is suspected, stop affected work and escalate for containment/rotation by Owner. If test fixture, record false-positive evidence and propose narrow remediation under separate Issue; never weaken scanner. For Go CI capture exact workflow/job/step/toolchain/log/exit evidence if accessible; compare identical commands and inputs, do not infer same root cause from equal failing conclusions. Keep any fixes outside P01; no waiver by baseline status.
4. Independently check receipt integrity, candidate fingerprint before/after each audit, real scope and state transitions. Missing CI access or unavailable hardware is NOT_VERIFIED; synthetic RF timing evidence is not HIL/RF.
5. Run approved benchmark pilot only if isolation, budget and oracle are established; otherwise produce protocol with baseline metrics NOT_RUN. Include matched domain-routing tasks, mandatory rule recall/coverage, irrelevant context load, skill activation failures, discovery cost and unauthorized-activation rejection; freeze criteria before P02. Do not change oracle or tune Harness during P01.
